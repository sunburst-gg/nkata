# Decisions

Append one line per decision: date, what, why, alternative rejected.
- 2026-10-01: Cloud sessions push to the session branch and `.github/workflows/ff-main.yml` fast-forwards main when `make test` is green. Terminal sessions push to main directly. Why: the harness owns the branch name in cloud sessions. Rejected: force-pushing main from a cloud session.
- 2026-10-01: `make test` falls back to local Postgres and MinIO binaries when Docker is absent (scripts/testenv.sh). Why: cloud sessions have no Docker daemon. Rejected: skipping the gate test without Docker, which would let the gate go untested.
- 2026-10-01: Dependency: zod 4 in shared. Why: CLAUDE.md names it, and Zod 4 ships z.strictObject and z.discriminatedUnion. Rejected: valibot.
- 2026-10-01: Dependency (dev): ajv 8 and ajv-formats in shared. Why: validates the JSON Schema files themselves and gives a third, independent validator in the round-trip test. Rejected: trusting the Zod output alone.
- 2026-10-01: Dependency (dev): typescript 5.9, vitest 3, tsx 4 at the workspace root. Why: CLAUDE.md pins TypeScript 5; vitest runs ESM TypeScript with no build step; tsx runs scripts and the server in dev. Rejected: jest and ts-node, both need extra ESM config.
- 2026-10-01: JSON Schema is the source of truth and the generator is in-repo (shared/src/emit-*.ts) for a documented subset. Why: CLAUDE.md says protocol types live as JSON Schema; the subset is small and a hand-written emitter has no dependency. Rejected: json-schema-to-zod and datamodel-code-generator, two more dependencies for the same output.
- 2026-10-01: Python generated package is `shared/py/` as the task says; the Blender add-on and UE5 plugin will vendor it under the name `nkata_shared`. Why: `py` is a poor import name outside tests. Rejected: renaming the folder, which the task file fixes.
- 2026-10-01: Dependency: fastify 5, @fastify/websocket 11, fastify-type-provider-zod 7 in server. Why: CLAUDE.md names Fastify 5 and the Zod type provider; v7 is the first line that takes Zod 4. Rejected: hono, no WebSocket plugin with the same maturity.
- 2026-10-01: Dependency: drizzle-orm 0.45, drizzle-kit 0.31 (dev), pg 8 in server. Why: CLAUDE.md names Drizzle on Postgres 16; node-postgres is the driver Drizzle's own quickstart uses. Rejected: postgres.js, same features, one less battle-tested with Drizzle migrations.
- 2026-10-01: Dependency: @aws-sdk/client-s3 and @aws-sdk/s3-request-presigner in server. Why: CLAUDE.md names them for presigned URLs on MinIO and R2. Rejected: minio-js, which ties the server to one vendor.
- 2026-10-01: Dependency: ulid 3 in server. Why: IDs are ULIDs; the monotonic factory keeps event ids ordered within a process. Rejected: ulidx, same API, smaller community.
- 2026-10-01: Added table auth_token (magic links and sessions) on top of the data model. Why: a magic link must be single use and a session must be revocable, both need a row. Rejected: signed stateless tokens, which cannot be single use.
- 2026-10-01: chunk is unique on (studio_id, blake3), not blake3 alone. Why: docs say dedupe is per studio; the store key carries the studio id so one studio cannot read another's bytes. Rejected: global dedupe.
- 2026-10-01: event rows carry project_id. Why: the index event (project_id, created_at) in the data model needs the column. GET /events?since= takes the last event id as cursor; ULIDs sort by time with no ties.
- 2026-10-01: Server REST request and response shapes are Zod in server/src/routes, composed from shared types. Why: shared owns the agent protocol, events, template, and checks as the task lists; the REST surface has one TypeScript consumer in step 2. A server.schema.json in shared comes when a second client appears.
- 2026-10-01: File sync routes beyond the doc list: POST /files/uploaded (server HEADs each object and records the chunk row), POST and GET /projects/:id/file-versions (the agent posts a file_version after upload and pulls the stream by id cursor). Why: the doc says the agent posts the file_version but names no route; HEAD on confirm keeps the server off the byte path.
- 2026-10-01: Part mapping at asset creation: blend_collection is <asset>/<part>.blend with the part as collection; ue_asset fills the template export ue_path; ue_actor is level <asset>, actor from export name; file is <asset>/<part>. Why: the doc gives the shapes but not the fill rule. Rejected: asking the art director for a path per part at creation, which breaks the one-screen rule.
- 2026-10-01: Dependency: fastcdc 3 (v2020 StreamCDC), blake3 1, rusqlite 0.37 bundled, notify 8 with notify-debouncer-full 0.5, reqwest 0.12 (rustls), tokio 1, clap 4, serde and serde_json, thiserror 2, tracing and tracing-subscriber (json), ulid 1, walkdir 2 in the agent crate; tempfile 3 for tests. Why: each is the crate CLAUDE.md names or the standard choice for its job. Rejected: openssl-backed reqwest (build pain on Windows), sqlx (async adds nothing for a local index).
- 2026-10-01: The agent index and temp files live in `<project>/.nkata-agent/` by default, not `~/.nkata/<project>/`. Why: the temp file for an assembled download must sit on the same filesystem as its target so rename is atomic; one folder keeps index and temp together. The CLI takes --index to override. The folder is always ignored by scans.
- 2026-10-01: Push confirms uploads in batches of 64 chunks through POST /files/uploaded. Why: a push interrupted mid-batch re-sends at most 64 chunks (128 MB at the 2 MB target) on the next run, and the server HEADs each object so a lost PUT is never recorded. Rejected: confirming per chunk (one extra request per 2 MB).
- 2026-10-01: Pull skips a path whose local copy has unsent changes and reports it as a conflict. Why: locks (step 3) stop two people editing one part; until then the agent must not overwrite local work. Rejected: remote wins.
- 2026-10-01: Step 2 gate green in `make test` (desktop/src-tauri/tests/sync_gate.rs). 2,202,009,602 bytes in 106 files (5 x 400 MiB, 100 x 1 MiB, one small), 927 chunks. First push 41.6 s, first pull 52.5 s, both through local MinIO on a 4 core cloud container. A 4 KB edit in the middle of a 400 MiB file moved 1 chunk, 1,966,484 bytes: push 5.2 s, pull 9.1 s. Chunking and hashing run with optimized dependencies in dev and test profiles (workspace Cargo.toml) so the gate is bound by disk and network.
- 2026-10-01: Added Viewer role to docs/product.md, docs/engineering.md, and the shared Role enum. Why: investors, publishers, outside writers, and voice directors need to see and comment on the project without Blender, UE5, or a synced folder. Rejected: a read-only web viewer first, which the product doc keeps for later.
- 2026-10-01: Dependency: axum 0.8 and tokio-stream 0.1 in the agent crate for the local API and SSE; futures-util 0.3 for tests. Why: axum is the tokio project's own HTTP framework and ships SSE; the agent already runs on tokio. Rejected: warp (less active), actix-web (its own runtime).
- 2026-10-01: Dependency (dev tool): ruff, installed by scripts/test.sh with pip when missing. Why: CLAUDE.md requires ruff clean Python. Rejected: flake8 plus isort, two tools for one job.
- 2026-10-01: The Rust agent keeps hand-written serde mirrors of the shared agent protocol types (desktop/src-tauri/src/protocol.rs). Why: the task names Python and TypeScript generation only. tests/protocol_conformance.rs validates every Rust type's JSON against the generated Python validators so drift fails the build. A Rust emitter can replace the file later with no other change.
- 2026-10-01: The agent token file is <project>/.nkata-agent/token. Editors find the project root by walking up from the open file to the folder that holds .nkata-agent/. Why: no global config to install, and one project folder per agent. NKATA_AGENT_TOKEN and NKATA_AGENT_URL override it for tests.
- 2026-10-01: The spool is <project>/.nkata-agent/spool/<part_id>/<ulid>.glb with <ulid>.manifest.json and <ulid>.args.json beside it. Why: same folder as the index (see the step 2 decision), pruning after 7 days is one directory walk. The agent writes the UE5 script arguments to the args file and passes its path; JSON on a command line is fragile.
- 2026-10-01: Mirror destination for a blend_collection or file part is /Game/Nkata/<asset>/<part> until step 3 applies the template export rules. ue_asset parts use their mapped path. Why: step 1 needs a fixed target with no template plumbing.
- 2026-10-01: The agent runs one UE5 import at a time. Why: the editor runs Python on the game thread; parallel calls queue there anyway and interleave their log output.
- 2026-10-01: Open question (needs Blender 4.2): the collection exporter call. export.py sets exporter.export_properties.filepath and calls bpy.ops.collection.exporter_export(index) under a context override with the collection, and falls back to bpy.ops.export_scene.gltf with use_active_collection. Confirm the operator name, the property path, and that the override is read, on a real file.
- 2026-10-01: Open question (needs UE 5.4): glTF reimport options. import_part.py uses FbxImportUI for .fbx and InterchangeGenericAssetsPipeline for .glb, passing the existing skeleton and physics_asset on reimport. Step 0 (measure on the real Rising Sun character) has not run. Confirm the pipeline property names, that replace_existing keeps material slots, and the time on a real character. If Interchange cannot keep the physics asset, export FBX from the collection exporter instead.
- 2026-10-01: Open question (needs both editors): the e2e timing. e2e/mirror.py measures from the Blender save to the mirror.result on SSE. The gate is p95 under 10 s over 20 saves. Not yet measured.
- 2026-10-03: Refocus on four people (docs/tasks/refocus.md). Template schema gains `kind` (character, prop, level_area) and the part mapping gains `ue_area` {level, area}. Why: the agent picks the import script by kind and a level area is a set of tagged actors, not one actor. Rejected: inferring the kind from the part names, which breaks on the first renamed template.
- 2026-10-03: A level area asset is named "<level> / <area>" (Enugu Market / square) and every part of it maps to the same {level, area}; the parts are the phases of one area (blockout, layout, set dressing, lighting). Why: one tag per area keeps the actor scan simple. Rejected: one tag per part, which would split one area's actors four ways.
- 2026-10-03: Role enum cut to artist, art_director, producer, viewer. The viewer refusal is one onRequest hook in server/src/app.ts: a viewer-only principal gets 403 on every non GET route except POST /comments, /comments/:id/resolve, and /files/download-urls. Why: one boundary cannot be forgotten on a new route. Rejected: a requireRole call per route, which the next route would miss.
- 2026-10-03: Migration 0001 drops comment.linear_issue. Forward only; the reverse is a nullable column add, which loses no data. Why: Linear is in Later and a dead column invites a dead field on the wire. Rejected: keeping the column unused.
- 2026-10-03: Stream mode (viewer) lives in desktop/src-tauri/src/stream.rs: `nkata-agent init --stream`, `fetch`, and `serve --cache`. The cache root is ~/.nkata/<project>/cache (NKATA_HOME overrides ~/.nkata), a SQLite table beside the files, 5 GB cap, least recently used by a per-touch sequence number. GET /projects/:id/file-versions/:fvid added so a viewer fetches one version without paging the stream. Why: a viewer has no folder and no index. Rejected: a dirs crate for the home folder, one env var is enough; wall clock for LRU order, which ties within a millisecond.
- 2026-10-03: MeResponse gains `mode` (sync or stream). In stream mode POST /parts/:id/saved is 403 and the mirror runner does not start. Why: the editors must know they are talking to a viewer agent.
- 2026-10-03: The mirror is split by template kind. PartSummary and ObjectManifest carry `kind`; the agent picks import_character.py for a character, import_static.py for a prop, and skips the mirror for a level area (its actor files sync like any file). import_part.py is deleted. Why: a skeletal reimport and a static reimport keep different things and one script that guesses from the existing asset guessed wrong on first import. Rejected: one script with a kind switch, which would keep the guess.
- 2026-10-03: A prop export is refused in Blender when any object's scale is not 1 (within 0.0001) or its origin is more than 1 mm above the base of its world bounds. The save still records a version with changed false and the panel shows the reason. Why: a placed copy inherits the pivot, so a wrong origin is wrong in every level. Rejected: fixing the origin in the export, which would move the artist's object under them.
- 2026-10-03: Open question (needs UE 5.4): import_static.py sets Nanite, LOD group, and collision through FbxImportUI.static_mesh_import_data for FBX and through the Interchange mesh pipeline for glTF, and counts referencers with EditorAssetLibrary.find_package_referencers_for_asset. Confirm the property names, that a glTF reimport keeps material instances, and that One File Per Actor referencers list the actor packages.
- 2026-10-03: Checks ship as two template lists (docs/engineering.md, Checks) with `pivot_at_base` added, nine contracts in all. Blender owns eight of them in blender-addon/nkata/checks.py as pure functions over SceneFacts, gathered by save_hook.gather_facts; UE5 owns lod_count, collision_present, metahuman_dna_present, and the UE5 side of triangle_budget and name_pattern in ue5-plugin/scripts/checks.py. Why: a check that can run without the editor is tested without it. Rejected: one Python module shared by both editors, which would import bpy and unreal in one file.
- 2026-10-03: Migration 0002 adds version.refs (jsonb, [{level, actors}]). After a static import the agent runs scan_refs.py and sends the levels with the mirror result; a scan failure is logged and never fails the mirror. Why: where a prop is placed is the one piece of the dependency map v1 keeps (docs/product.md, Later). Rejected: a refs table, one row per level, more joins for one list the app shows whole.
- 2026-10-03: Desktop interface audit done (desktop/DECISIONS.md). The Blender N-panel and UE5 panel elements that need Publish, checks, comments, and presence routes on the agent land with step 3 (docs/tasks/03-parts-locks.md); the panels keep the two elements that have data today.
- 2026-10-03: Fixture corpus in fixtures/, built by fixtures/build.py with a plain Python glTF 2.0 writer: one rigged character (20 bones, two materials, a 1024 texture), three props (two boxes on the origin, one LOD1, a collision box), one level area (eight tagged actors as JSON). 296 KB checked in. Why: tests without an editor need real shapes, and a dependency-free writer keeps the build to one command. Rejected: committing real Rising Sun assets (large, not ours to publish) and a glTF library (one more dependency for 200 lines).
- 2026-10-03: The quality bar is e2e/quality.py (@needs_editor) with e2e/panel_probe.py inside Blender, and e2e/environment.py is the step 1b gate script. The parts that need no editor run in make test: lost save and queue drain in desktop/src-tauri/tests/lost_save.rs (a push killed mid upload drains on the next run and a second machine gets every byte), role refusals in server/test/api.test.ts, cache eviction in stream.rs and tests/stream_mode.rs. Why: every measure has one owner and one place to read it.
- 2026-10-03: Open question (needs both editors): the quality bar numbers. Mirror p95 for a character and a prop, broken links over 20 reimports, placed copies in two levels, and the panel open time are unmeasured; e2e/quality.py prints them. The lost save measure is green in make test.
- 2026-10-03: Open question (needs UE5): e2e/environment.py and e2e/quality.py assume the fixture prop is placed in two levels before the run and that scan_refs.py sees One File Per Actor packages as referencers. Confirm on a real project.
