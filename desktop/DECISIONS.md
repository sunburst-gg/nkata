# Desktop app decisions

Calls made where the handoff and the product docs were silent. One decision each, then on.

1. **React 19, not 18.** CLAUDE.md pins React 19 for the desktop and shadcn's Radix primitives support it. Nothing in the handoff depends on 18.
2. **Tailwind 4 mapped to the token variables.** `@theme inline` in `src/styles/app.css` turns every `--bg-*`, `--fg-*`, `--state-*`, radius, shadow, and font token into a utility (`bg-panel`, `text-secondary`, `border-hairline`, `rounded-xl`). Components carry no hex; a test (`src/lib/hex.test.ts`) fails the build if one appears in components, screens, or the store.
3. **shadcn patterns without the shadcn CLI.** Dialog, DropdownMenu, Tooltip, Toast, Tabs, and Avatar are Radix primitives wrapped and styled to the tokens by hand in `src/components/`. The CLI output would have been restyled line by line anyway.
4. **Hash routing.** The Tauri window serves one `index.html`; a deep link on a path route has nothing to fall back to in a packaged build. Routes read `/#/p/rising-sun/a/ojukwu` with the paths the prompt lists after the hash.
5. **Fonts from the geist package, bundled.** `src/styles/fonts.css` declares `@font-face` for the variable Geist and Geist Mono WOFF2 files and Vite hashes them. The Google Fonts import was removed from the copied `typography.css`. No network at runtime.
6. **Avatar tones live in `src/styles/avatars.css`.** The prototypes color each person with one of eight muted hues that `tokens.json` does not hold. They are `--avatar-1` to `--avatar-8` plus `--avatar-fg`, `--scrim`, `--on-scrim`, and `--preview-bg`, the only color values outside the token files. Components reference the variables.
7. **Copy keys are exact; repeated placeholders take an array.** `project.status` repeats `{n}` three times, as the handoff lists it. `t("project.status", { n: [6, 14, 4] })` fills them in order. Strings the prototypes show on screen but the handoff does not key (`viewer.status`, `preview.none`, `digest.home`) were added under the same voice.
8. **Permissions in one place.** `src/auth/permissions.ts` holds `can(action, role)`. Screens call `useCan()` and never read the role. For a viewer, a control that `can()` denies is not rendered. Review is a filter on the project screen, so every non viewer has it; Approve, Send back, Remove gate, and Assign are for art directors and producers; Invite and Settings are for producers, as the product doc's roles table says. The prototype shows Invite to an artist; the product doc wins.
9. **Ready count counts Ready parts.** The status line and the Review button count parts in Ready across the project, and the Review filter shows every asset with a Ready part, oldest first. The prototype hard codes 4.
10. **Tauri is a Cargo feature.** The window binary `nkata-desktop` needs WebKit on Linux. `desktop/src-tauri/Cargo.toml` puts `tauri` behind the `desktop` feature, `tauri.conf.json` passes it, and `make test` builds the agent and the CLI without it.
11. **A window hook for screenshots.** `window.__nkata` switches the mock role, opens the rail, and sets review mode so `pnpm shots` can walk every state in one build. It exists while the data is the in memory mock and leaves with the real `DataSource`.
12. **Turntable fallback is a pan.** `RotatablePreview` scrubs frames when it has several; with one render it pans the image on drag so the gesture still reads, as the prototype does. `ModelViewer` is the slot for three.js and glTF.
13. **Vite 7 with vitest 3.** vitest 3 pins Vite 7; `@vitejs/plugin-react` 5 matches. Vite 8 waits for vitest 4.
