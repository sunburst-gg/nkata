# Desktop app decisions

Calls made where the handoff and the product docs were silent. One decision each, then on.

1. **React 19, not 18.** CLAUDE.md pins React 19 for the desktop and shadcn's Radix primitives support it. Nothing in the handoff depends on 18.
2. **Tailwind 4 mapped to the token variables.** `@theme inline` in `src/styles/app.css` turns every `--bg-*`, `--fg-*`, `--state-*`, radius, shadow, and font token into a utility (`bg-panel`, `text-secondary`, `border-hairline`, `rounded-xl`). Components carry no hex; a test (`src/lib/hex.test.ts`) fails the build if one appears in components, screens, or the store.
3. **shadcn patterns without the shadcn CLI.** Dialog, DropdownMenu, Tooltip, Toast, Tabs, and Avatar are Radix primitives wrapped and styled to the tokens by hand in `src/components/`. The CLI output would have been restyled line by line anyway.
4. **Hash routing.** The Tauri window serves one `index.html`; a deep link on a path route has nothing to fall back to in a packaged build. Routes read `/#/p/rising-sun/a/ojukwu` with the paths the prompt lists after the hash.
5. **Fonts from the geist package, bundled.** `src/styles/fonts.css` declares `@font-face` for the variable Geist and Geist Mono WOFF2 files and Vite hashes them. The Google Fonts import was removed from the copied `typography.css`. No network at runtime.
6. **Avatar tones live in `src/styles/avatars.css`.** The prototypes color each person with one of eight muted hues that `tokens.json` does not hold. They are `--avatar-1` to `--avatar-8` plus `--avatar-fg`, `--scrim`, `--on-scrim`, and `--preview-bg`, the only color values outside the token files. Components reference the variables.
7. **Copy keys are exact; repeated placeholders take an array.** `project.status` repeats `{n}` three times, as the handoff lists it. `t("project.status", { n: [6, 14, 4] })` fills them in order. Strings the prototypes show on screen but the handoff does not key (`viewer.status`, `preview.none`, `digest.home`) were added under the same voice.
8. **Permissions in one place.** `src/auth/permissions.ts` holds `can(action, role)`. Screens call `useCan()` and never read the role. For a viewer, a control that `can()` denies is not rendered. Review is a filter on the project screen, so every non viewer has it; Approve, Send back, Remove gate, and Assign are for art directors and producers; Invite and Settings are for producers, as the product doc's roles table says. The prototype shows Invite to an artist; the product doc wins.
9. **Ready count counts Ready parts.** The status line and the Review button count parts in Ready across the project, and the Review filter shows every asset with a Ready part, oldest first. The prototype hard codes 4.
10. **Tauri is a Cargo feature.** The window binary `nkata-desktop` needs WebKit on Linux. `desktop/src-tauri/Cargo.toml` puts `tauri` behind the `desktop` feature, `tauri.conf.json` passes it, and `make test` builds the agent and the CLI without it.
11. **A window hook for screenshots.** `window.__nkata` switches the mock role, opens the rail, and sets review mode so `pnpm shots` can walk every state in one build. It exists while the data is the in memory mock and leaves with the real `DataSource`.
12. **The model viewer is three.js.** `ModelViewer` is the React boundary around `nk-viewer`, the web component from `handoff/v3/nk-viewer.js` ported as is to TypeScript. It loads the GLB the Blender add-on exports, shows the latest render as the poster while it loads, and raycasts pins. The v2 turntable (`RotatablePreview`) went with v2.
13. **Vite 7 with vitest 3.** vitest 3 pins Vite 7; `@vitejs/plugin-react` 5 matches. Vite 8 waits for vitest 4.
- 2026-10-03: Refocus on four people. Roles in the app are artist, art director, producer, viewer. Tabs are All, Characters, Props, Levels. The mock drops the writer and the engineer, the script and sound assets and templates, and the Linear connection. Discord appears once in settings: one message on Approve or Send back. The empty preview case is the Kettle prop, whose concept and model have no published render yet.
- 2026-10-05: The server data source (src/data/server.ts) replaces the mock once someone signs in. It reads the REST routes into the screens' shapes, refreshes on every WebSocket event (one debounced reload, no per-event patching in v1), and sends every mutation to its route after updating the screen at once. The mock stays for the browser preview, the tests, and the screenshots; the store swaps sources with useSource. Renders are null until a render pipeline exists, so previews fall back to the empty state. Sign in is the magic link: a dev server answers with the link and the flow is three screens; a production server emails it and the person pastes it. The agent starts inside the window through Tauri commands: sync mode with a folder, stream mode for a viewer.
- 2026-10-10: The data layer carries the studio's training setting and billing line (Studio.training, Studio.billing, setTraining on the server source), a comment kind (pin or take_a_look) on every Comment, and the Tools report (lib/tools.ts). The screens read them when the v3 screens land. Sign in stays the magic link alone; Google comes as its own integration later.

## v3 (2026-10-10)

The v3 prototype (`handoff/v3/Nkata App v3.dc.html`) replaced v2 wholesale: Home, Changes, People, Templates, Profile, the five-step Create, States, and the Tools step are gone; the screens are Sign in, Name, Create studio, Welcome, New project, Project, Asset, Part, Connections, Mentions, Settings, with Members, Delete project, Create asset, Ask, and the full screen reviewer as overlays. Where v3 and the repo disagreed on a screen, v3 won; on an engine (agent, server, data, permissions), the repo won. Calls made where v3 was silent:

14. **`handoff/v3/tokens` did not exist.** The folder was created from `handoff/tokens` with the fixes the v3 prompt asks for: Newsreader in `tokens.json` `type.family`, `--font-serif` and `--role-moment` in `typography.css`, no Google Fonts import. `src/styles/tokens` is a copy; `pnpm tokens` regenerates `tokens.ts`. The light block takes v3's white page, translucent lines, and the slate Locked, green Synced, amber Syncing.
15. **Newsreader comes from `@fontsource-variable/newsreader`**, bundled next to Geist in `fonts.css`. Alternative rejected: the Google Fonts stylesheet the prototype links, which needs the network.
16. **three.js 0.186 is the one rendering dependency.** `nk-viewer.js` targets it and nothing lighter loads glTF with PBR materials. The Khronos Duck (`public/models/Duck.glb`, CC BY 4.0) is the mock's model for every asset so the viewer works offline; a real project loads the GLB the add-on exports per version.
17. **One viewer session in the store.** Pinning, the pending pin, the active pin, and the draft live in the store, so the asset screen, the part screen, and the full screen reviewer show the same pins and a pin dropped in one is the pin in the others. The asset screen shows every part's comments and pins over the asset's model; a comment posted there attaches to the first part. Leaving a model screen ends pinning and drops an unposted pin.
18. **A comment at the origin is a thread reply.** The server stores `point` on every comment; the app reads `[0, 0, 0]` as no pin, since no reviewer pins the exact origin.
19. **The status line counts Ready assets and other people.** "2 ready for review" is assets in Ready, as the v3 content shows, and the Review filter lists them. "3 online" leaves out the signed-in person and viewers. The rail and the status line appear once a project has more than its first asset.
20. **Connections come from the agent, not the server.** The Blender and Unreal cards read the Tools report (`agent.toolsDetect`); Connect installs the add-on or the plugin through the Tauri commands. The mock marks them by demo stage. Discord is the server webhook. The tool logos are Simple Icons SVGs vendored in `src/assets/logos` (CC0) with the prototype's colors; Substance has no mark and shows its initial.
21. **The sidebar and Settings for a viewer.** No New project, Invite members, or Billing rows, no "Invite and manage members" in the studio menu. Settings shows Account, Members (the list, no Add), Connections (no Connect), MCP and Agents. General, Billing, and Training are for producers; Appearance sits in General for everyone else who can see it. The prototype shows every row to every role.
22. **Local-only edits where the server has no route.** Rename and delete project, remove a member, the person's name and email, and the studio name change on screen at once and are not sent anywhere yet. The routes are the next server step.
23. **A studio-only session before the first project.** The server source loads with an empty project id (`/auth/me`, `/studio`, `/projects` only) so a new producer lands on Welcome and creates a project from there. The folder chosen at New project is kept per project in `localStorage` (`nkata.folders`); opening another project reconnects the agent to its folder, or to stream mode for a viewer.
24. **`tauri-plugin-dialog` for the folder picker**, behind the `desktop` feature with `dialog:default` in the capability and `@tauri-apps/plugin-dialog` in the window. Alternative rejected: typing the path, which the prototype replaced with Choose. The desktop binary does not build in the CI container (no WebKit), so the plugin registration is unverified until the first macOS build.
25. **Light is the default theme and the full screen reviewer is always dark.** `colors.css` gained a `[data-theme="dark"]` block so a dark element inside the light app takes the dark scale back. The toast is inverted (heading on canvas) so the one dark toast reads on both themes.
26. **The Welcome card pictures live in `welcome.css`.** They are pictures of the app on a blurred render with fixed colors; keeping them in CSS keeps `hex.test.ts` true for components.
27. **`window.__nkata` takes the prototype's Tweaks**: demo stage, role, theme, the rail, the tab, the overlays, and the full screen. `pnpm shots` walks every v3 screen through it at 1280 and 1440, light and dark.
28. **Ask is keyword matching** in `src/data/ask.ts`, shared by the mock and the server source, until Nok answers: the blocked asset, who owns it, the last comment, a link. The prototype's Ojukwu answer is the canned case.
29. **Rename is a dialog, Export on the project menu points at the asset.** The prototype's Rename and Export rows do nothing; Export is per asset in the engine (`GET /export/:asset`). Switch studio is a toast: one studio per account in v1.
30. **Create asset asks "All parts, or one?"** with one as the default for a prop and all for a character or level, as the engine decision of the same day. The first save in Blender gives the tile its render and the "synced to Unreal" toast; the mock plays that save 1.2 s after Create.
